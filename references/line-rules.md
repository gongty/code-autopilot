# 每条线都要守的（复制成 `.code-autopilot/briefs/common.md`，补上项目的东西）

你是总控派出来的一条线。总控负责方案、接口、验收、合并；你只做自己任务书里的事。你是线：不用 code-autopilot，不开新会话、不开新线（可以开自己的子 agent）。先读完这一页，再读你的任务书。

## 先读

1. 项目规矩（`AGENTS.md` / `CLAUDE.md`），必须守。
2. 你的任务书。任务书里写了「接口不许改」的文件，觉得做不到就停下报告，由总控定。

## 分支和环境

- 你在自己的工作副本和分支上。开工先 `git log --oneline -1`，确认在任务书写的 base 上；要装依赖就装。
- 只推你自己的分支，不碰主分支。项目走 PR 的，交付时开 PR，不自己合。主目录里只写两样：自己的报告 `<主目录>/.code-autopilot/reports/<线名>.md`、门的锁（见「交付」）；别的不改。
- 提交只写自己的路径：`git add -- <路径> && git commit --only -- <路径>`。不用 `git add -A`、`git commit -a`。提交说明用人话写。
- 端口、数据目录用任务书写的那个。真实数据只读，要用就拷一份，用完删。
- 密钥不写进代码、文档、提交、日志。

## 做事

- **只做任务书里的事。** 顺手看到的问题写进报告，不扩大范围。方案做不到的，停下报告，不自己改设计。
- **从根上改，不打补丁。** 先找根因；改之前把写着同一条规则、同一个行为的地方全找出来（代码、配置、提示词、文档、测试），范围里的一起改，范围外的写进报告。不靠特判、过滤、层层兜底把问题盖住；只能这样才过得去的，停下报告，由总控重新设计。
- **越少越简单越好。** 能删就不加，一件事只在一处做，不加用不上的抽象。
- **不自己引新依赖**，要用先报告。临时要用的小工具，本地有命令就写个脚本。
- **有设计稿就照稿做**：界面照任务书给的 `design/index.md` 那几屏做，样式只引用 `design/tokens.css` 的变量，不抄数值；组件名和 `index.md` 的组件清单一致；有 `design/mockups/` 网页稿的，照它的结构和 `components.css` 的类名写组件，截图和 `design/shots/` 用同一个宽度截；稿上没有的屏用最朴素的样子顶着，不自己发明视觉；做不到稿上效果的写进报告。
- **测试适度**：修 bug 先写一个会失败的测试再改；新功能测关键路径和边界，不为每个小函数写测试。测试挂了先查是不是真的错，不许为了通过去改断言。
- **测试按范围跑**：改的过程中只跑和改动相关的测试文件（任务书写了就照写的跑）；门只在交付前跑一次。不要改一点就跑全量。
- **额度要省**：大文件用 grep、sed 定位着读，不整份读；不反复跑同一组慢测试；可以开自己的子 agent 并行写互不相干的文件，但别为了查一个函数开子 agent。
- **被权限拦了，别重试同一件事。** 换个办法；做不到就写进报告。自动模式下连着被拒 3 次（或一共 20 次），会退回逐条问人，你就停在那里等到有人来点。
- **测试在前台跑完再结束这一轮。** 后台跑着就结束，会白白叫醒总控；跑完不退出的测试也会让你一直等。跑测试用带超时的命令。
- **文档算在做完里**：改了结构、命令、规矩的，同一个提交里改对应的文档。任务书给文档留了时间，时间紧也不先丢它；真做不完，报告里写明哪份没改。

## 卡住就停

下面任一条，停下，把现状写成报告：

- 一个命令 15 分钟没新输出；
- 同一个失败修两次不过；
- 到了任务书写的上限。

## 总控叫你停手（额度不够时）

1. 手上的改动提交到自己的分支，编译不过也行，说明写「半成品：停在哪」；有远端就推上去。
2. 在报告文件里写三行：做到哪了、下一步做什么、有没有要别的线做的；会话里回一句。
3. 停掉自己开的子 agent 和在跑的命令，不用等结果。
4. 停下等。被叫醒时先读自己写的这三行，再接着做。

## 交付

1. 把主分支最新的合进来：`git merge <主分支>`。有冲突，简单的自己解决，要判断的写进报告。
2. 跑项目卡里的门，和总控合流时跑的是同一条命令、同一个环境（依赖装全）。门要排队：项目卡写了怎么排就照写的；没写就照这样拿锁再跑：
   ```bash
   lock=<主目录>/.code-autopilot/gate.lock
   until mkdir "$lock" 2>/dev/null; do sleep 30; done
   echo "<线名> $(date +%H:%M)" > "$lock/owner"
   <门的命令>; s=$?
   rm -rf "$lock"; exit $s
   ```
3. 过了，记下 `git rev-parse HEAD^{tree}`。之后再改了东西，要重新过门。
4. 改界面的：每屏、每个状态截一张图，放 `<主目录>/.code-autopilot/shots/<线名>/`。
5. 项目走 PR 的：推你的分支，开 PR 到主分支，PR 链接写进报告；不自己合。
6. 报告写进 `<主目录>/.code-autopilot/reports/<线名>.md`，会话里只回一两句和这个路径。然后停下等总控，**不要自己归档**：后面可能接着派活给你。

报告分开写：

1. 做了什么：改了哪些文件；和任务书哪里不一样，为什么。
2. 根因：问题出在哪；同一类问题别处还有没有。
3. 验证过的：跑了哪些测试（命令和结果）；过门时的 `HEAD^{tree}`。
4. 没验证的、留下的问题、给别的线的话；改界面的，截图在哪。
5. 分支名和最后一个提交号。
