# 模型对照：每一档现在是哪个模型

`SKILL.md` 和别的文件只说档：**最强、中档、便宜**，另有比最强还贵的**最贵**。各家每档对应哪个型号、默认开多少思考强度，只写在这一页。模型换代了，只改这一页。

查于 2026-11-16，是作者的用法。

## 每档是哪个

| 档 | 用在哪（见 `SKILL.md` 第三节） | Claude | Codex |
| --- | --- | --- | --- |
| 最强 | 总控；要判断边界、设计方案的线；调研现成项目、项目梳理；设计线；碰核心的审查 | Opus 5.5 | Astra 6 |
| 中档 | 照单执行的线；改了一般行为的审查；对稿 | Sonnet | 6.1 sol |
| 便宜 | 只读的大范围查找（子 agent）；写文档这类照单的小活 | Haiku | 6.1 sol |
| 最贵 | 默认不用；真要用先问用户、说清为什么 | Fable | 没核 |

- Codex 里复杂、要设计方案的用 Astra 6；简单、任务书写清楚的用 6.1 sol 完全够。Codex 没有单独的便宜档，查找也用 6.1 sol。
- 设计线只有 Claude 有（Claude Design），Codex 没有，见 `design.md` 最后一节。
- WorkBuddy 能选的模型不一样，照这张表的思路：总控用最强的，照单执行的用便宜一档。

## 思考强度

五档：低（low）、中（medium）、高（high）、超高（xhigh）、极高（max）。Claude Code 开线时写 `effort`，子 agent 在 frontmatter 写 `effort`；Codex 写 `model_reasoning_effort`，或 `/model --reasoning=<档>`。

| 谁 | 档 | 思考强度 |
| --- | --- | --- |
| 总控 | 最强 | 超高 |
| 要设计方案的线、设计线、调研和梳理 | 最强 | 高 |
| 照单执行的线、审查、对稿、查找 | 中档或便宜 | 中 |

极高基本不用：慢、费额度，还爱自己扩大范围。线的模型和思考强度不能高于总控，所以总控开最强档 + 超高，正好都盖得住。

## 换代了怎么改

1. 改上面「每档是哪个」的表：每档换成新型号。
2. 新型号的能力和价钱挪了档的（比如新的中档比原来的最强还强），按「用在哪」一列重新对一遍。
3. 改「用到模型 id 的地方」，再照它改 `tools.md`「上下文」那段 JSON 里的 id。
4. 别的文件只写档，不用改。改完 grep 一下旧型号名，确认没漏：`grep -rn "<旧型号名>" .`
