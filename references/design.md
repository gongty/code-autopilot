# 设计线：总控怎么和 Claude Design 协作

只有 Claude Code 有这个模式：设计线是一条普通的线（独立会话），在里面用 Claude Design 出稿，也就是 Claude 里的 Design 画布，在 Artifact 里选 Design 类型。独立网站 claude.ai/design 2026-12-14 关闭，已经并进 Claude（Claude Code 工具说明原文，2026-11-16）。

做法来自一个真项目：总控写好给 Claude Design 的总纲和分批任务，设计在同一个对话里一批批出稿，存进仓库的 `design/`，研发照这个目录做界面。

## 什么时候开

- 新项目、有界面的大功能：开工第一批就开，和骨架线同时跑。
- 等设计的只有界面线；数据、接口、后台的线照常开。
- 设计没到的屏，界面线用最朴素的样子顶着，不自己发明视觉。

## 总控的活：把需求写清

照 `templates/design-brief.md` 写 `.code-autopilot/design/brief.md`：

- **总纲**：产品是什么、给谁用、什么气质；一定要有的和「不要出现」的；平台和尺寸（手机还是桌面、要不要深色模式）；交付物。
- **分批**：每批几屏。每屏写清放什么内容、有哪些状态（空的、加载中、失败、内容很多）、从哪进来、点了去哪。
- **我替你定的**：需求里没定、出稿又必须有答案的，总控先定，写「定成什么、为什么」，用户不同意再改。
- **你定的**：用户在稿子上定下的，记原话和日期，后面每一批照着做。

## 三种交法（用户选，记进项目卡）

| | 直接出 | 先挑方向 | 每批都看 |
| --- | --- | --- | --- |
| 视觉方向 | 设计线照总纲直接定一个，写下理由 | 出两三个方向，用户挑 | 同左 |
| 每一批 | 自检过了直接做下一批 | 第一批用户看过，之后自己一批接一批做完 | 每批用户看过才做下一批 |
| 设计线停下找人 | 要推翻总纲时找总控 | 要改定下来的方向、或要求互相矛盾时找用户 | 每批交了都等 |
| 界面线什么时候开 | 一批交了，总控验收后就开 | 方向定了、那一批交了就开 | 用户看过那一批才开 |

- 用户没回话（比如睡了）先按「直接出」做，用户看了要改再改。
- 等用户看稿时，在 `notes.md` 记「等用户看设计」。巡检不算设计线卡住，只告诉用户稿子在哪。
- 用户可以点进设计线的会话直接说，也可以在设计稿上留言。

## 开设计线怎么说

```
你是设计线。先读 <主目录>/.code-autopilot/design/brief.md 和项目规矩。
用 Claude Design 出稿（Artifact 选 Design 类型）。交法：<直接出 / 先挑方向 / 每批都看>。
同一个会话里一批接一批做：换了会话，定下的规范和组件就得重新交代。
每做完一批：
1. 照 brief 末尾的「出稿后怎么看」自己过一遍，用浏览器实际打开看，有问题先改。
2. 出稿存进 design/：可交互的 HTML、写成 CSS 变量的设计规范、组件清单、能点到每一屏的 design/index.html。只提交 design/ 下自己的文件。
3. 回给总控三行：做到第几批、设计稿链接、入口文件；哪些文案是你补的、哪些状态没做。
只在交法写的那几种情况停下找人，别的自己定，定了什么最后一起说。
```

模型用 Opus，思考强度高。做完别归档：下一批、改稿都发给它。

## 界面线怎么接

- 任务书写上设计稿链接、`design/` 里对应的入口和批次。
- 照稿做；做不到的写进报告，不自己改设计。
- 验收时截图对着稿看。

## 改设计

定了稿就像定死的接口：要改，由总控发给设计线出新一版（旧版留着对比），改完再告诉用到它的界面线。

## 没有 Claude Code 的时候

Codex、WorkBuddy 开不了设计线。总控照样写 brief，请用户拿到 Claude 里出稿，出稿放进 `design/`，界面线照样照 `design/` 做。
