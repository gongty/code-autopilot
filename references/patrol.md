# 巡检、停手、续上、纠正：四段可以直接用的提示词

尖括号里的换成你的。定时怎么建见 `tools.md`。

## 1 循环巡检（每 20 分钟，错开整点）

定时：`7,27,47 * * * *`

```
巡检（<这一阶段的名字>，计划 .code-autopilot/plan.md）。要轻，少读：
1) 先读 .code-autopilot/notes.md。查额度：5 小时用了多少、几点重置、周额度。按最近两次读数的涨速推到重置时，超过 85% 就按 <E→D→C→B> 的顺序让线停在一个提交上等（<A> 最后停）；同时建一个重置后 4 分钟的一次性续上定时，id 记进 notes.md。读数记进 notes.md。
2) 看 <线名列表> 的状态。对在跑的：看分支上最新提交（git -C <工作副本> log -1）、最近的进程输出，和任务书的预计、上限比还剩多少。
3) 卡住就当场发话纠正：一个命令 15 分钟没新输出、CPU 满着不出结果或很低却不退出、原地打转、超上限、跑题。线在等卡住的命令时读不到消息：先 stop_session 打断它这一轮，再发话；命令还在的，按 patrol.md 的表找到那个进程停掉（不停线自己的 claude 进程）。
4) 有线交了（报告在 .code-autopilot/reports/）：照 code-autopilot 第七节验收、按风险分档审查，过了合进本地主分支，接着派下一步。
5) 没有在跑的、停手等重置的、等开工的线了，才删掉这个巡检。
“还在跑”不算进展。只在有事时写一两句话。
```

每次派新活、换线，就删掉旧巡检、按新的线名和任务重建一个（提示词里写清每条线的任务书路径、开工时间、上限到点时刻）。

## 2 叫一条线停手（额度不够）

```
<线名>（总控）：额度涨得太快，先停一下，<重置时刻> 重置后我叫你接着做。

现在就收：
1. 把手上的改动提交到你的分支。编译不过也行，说明写“半成品：停在哪”。有远端就推上去。
2. 在报告文件里写三行：做到哪了，下一步做什么，有没有发现要别的线做的；会话里回一句。
3. 停下等。不要再开子 agent，也不要跑测试。已经在跑的子 agent 和命令，让它们停掉，不用等结果。
```

总控这边同时：建好续上定时（第 3 段）；所有线都停了的话，后台跑 `caffeinate -i -t <到重置后 10 分钟的秒数>`，别让机器闲置休眠。

放行：

```
<线名>（总控）：额度还够你再做一段，接着做，我在快到线时叫停。先把主分支最新的合进来（git merge <主分支>，现在是 <提交号>），<这期间变了什么>。
```

## 3 一次性续上（重置后几分钟）

在会话里的定时（`CronCreate`）：cron 写死日期，只跑一次，如 05:00 重置：`4 5 <日> <月> *`，`recurring: false`。用桌面端的「定时任务」就用 `fireAt`（一个时刻），别写 cron，cron 会变成每年那天都跑。

```
<重置时刻> 额度重置了。
1) 查额度，确认 5 小时那项已经归零。
2) 给等着开工的线发“开工”，照它的任务书做：<线名>。
3) 因为额度停下的线，逐个叫醒：“额度已重置，先读你上次写的现状，接着做”。
4) 照 .code-autopilot/plan.md 的时间表核对进度，晚了的找原因。
5) 有线在跑了，确认巡检还在，没有就重建。
```

## 4 纠正卡住的线（写清看到了什么）

```
<线名>（总控）：你在跑的 <命令> 卡住了，我先打断了你这一轮，停掉了 <进程>。<日志> 从 <时刻> 起没有新输出；<文件 1>、<文件 2> 的进程 CPU 一直 100%，已经 <N> 分钟。
CPU 满着、超时又一直没触发，说明有同步的循环占住了。
1. 单独跑 <其中一个>，找到转圈的地方，从根上改。
2. 这几个都单独过了，再跑整套。
3. 跑测试时不要留没人管的后台进程。
```

## 判断卡住时看什么

| 看什么 | 怎么看 |
| --- | --- |
| 线的状态 | 会话列表（在跑 / 闲着 / 等你） |
| 分支最新提交 | `git -C <工作副本> log -1 --format='%h %cr %s'` |
| 在跑的命令 | 找在这个工作副本里跑的进程：`lsof -d cwd \| grep -E ' <工作副本路径>(/\|$)' \| grep -v -E '^(claude\|disclaim)'`。第二列是 pid；按进程所在目录找，相对路径起的命令也抓得到。路径要整段对上（`…/worktrees/a` 不是 `…/worktrees/ab`）；`claude` 是线自己的会话、`zsh` / `bash` 是它的命令行，都别停。再看跑了多久、CPU：`ps -o pid,etime,%cpu,command -p <pid>`。只停确认过的测试、构建进程 |
| 输出动没动 | 日志文件的修改时间：`stat -f %Sm <日志>`（macOS）、`stat -c %y <日志>`（Linux） |
| 离上限多远 | notes.md 里的开工时间 + 上限 |
