# 巡检、停手、续上：三段可以直接用的提示词

尖括号里的换成你的。定时的写法见 `tools.md`。

## 1 循环巡检（每 20 分钟，错开整点）

定时：`7,27,47 * * * *`

```
巡检（<这一阶段的名字>，开发计划 <路径>）。要轻，少读：
1) 先读 .code-autopilot/notes.md。查额度：5 小时用了多少、几点重置、周额度。按最近两次读数的涨速推到重置时，超过 85% 就按 <E→D→C→B> 的顺序让线停在一个提交上等（<A> 最后停），重置后再叫醒。读数记进 notes.md。
2) 看 <线名列表> 的状态。对在跑的：看分支上最新提交（git -C <工作副本> log -1）、最近的进程输出，和任务书的预计、上限比还剩多少。
3) 卡住就当场发话纠正：一个命令 15 分钟没新输出、CPU 满着不出结果或很低却不退出、原地打转、超上限、跑题。线在等卡住的命令时读不到消息，先停掉那个进程。
4) 有线交了报告：照 code-autopilot 第六节验收（看报告、diff --stat、抽看关键改动、开一个不是作者的审查子 agent），过了合进 <集成分支>，接着派下一步。
5) 没有线在跑了，删掉这个巡检。
“还在跑”不算进展。只在有事时写一两句话。
```

每次派新活、换线，就删掉旧巡检、按新的线名和任务重建一个（提示词里写清每条线的任务书路径、开工时间、上限到点时刻）。

## 2 叫一条线停手（额度不够）

```
<线名>（总控）：额度涨得太快，先停一下，<重置时刻> 重置后我叫你接着做。

现在就收：
1. 把手上的改动提交到 <分支>。编译不过也行，说明写“半成品：停在哪”。推上去。
2. 在这个会话里写几行：做到哪了，下一步做什么，有没有发现要别的线做的。
3. 停下等。不要再开子 agent，也不要跑测试。已经在跑的子 agent 和命令，让它们停掉，不用等结果。
```

放行：

```
<线名>（总控）：额度还够你再做一段，接着做，我在快到线时叫停。先 git merge <集成分支>（<提交号>），<这期间变了什么>。
```

## 3 一次性续上（重置后几分钟）

定时：重置时刻 + 4 分钟，只跑一次（如 05:00 重置：`4 5 <日> <月> *`）。

```
<重置时刻> 额度重置了。
1) 查额度，确认 5 小时那项已经归零。
2) 给等着开工的线发“开工”，照它的任务书做：<线名>。
3) 因为额度停下的线，逐个叫醒：“额度已重置，先读你上次写的现状，接着做”。
4) 照开发计划的时间表核对进度，晚了的找原因。
```

## 4 纠正卡住的线（写清看到了什么）

```
<线名>（总控）：你在跑的 <命令> 卡住了，我先停掉了它和下面的进程。<日志> 从 <时刻> 起没有新输出；<文件 1>、<文件 2> 的进程 CPU 一直 100%，已经 <N> 分钟。
CPU 满着、超时又一直没触发，说明有同步的循环占住了。
1. 单独跑 <其中一个>，找到转圈的地方，从根上改。
2. 这几个都单独过了，再跑整套。
3. 跑测试时不要留没人管的后台进程。
```

## 判断卡住时看什么

| 看什么 | 怎么看 |
| --- | --- |
| 线的状态 | 会话列表（在跑 / 闲着 / 等你） |
| 分支最新提交 | `git -C <工作副本> log -1 --format='%h %cr %s'` |
| 在跑的命令 | `ps -o pid,etime,%cpu,command -p $(pgrep -f <工作副本路径>)` |
| 输出动没动 | 日志文件的修改时间：`stat -f %Sm <日志>`（macOS） |
| 离上限多远 | notes.md 里的开工时间 + 上限 |
