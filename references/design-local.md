# 本地出稿：没有 Claude Design 时，设计线怎么出稿（设计线读的）

总控开设计线前，把这页复制成 `.code-autopilot/design/rules.md`。Claude Code 里照旧用 Claude Design，不用这页；Codex、WorkBuddy 这些没有 Claude Design 的环境用这页。

你是设计线：照总纲 `.code-autopilot/design/brief.md` 出稿，交到仓库的 `design/`，界面线照着做。没人盯着看稿（全自动）也要出好效果，所以这页和 Claude Design 有一处不同：**你自己截图、自己看，再派一个不是你的子 agent 审稿**，改到过关才交。总纲、分批、交法、对稿照 `design.md`，这页只管出稿。

## 交什么

```
design/
  tokens.css          规范写成 CSS 变量：颜色、字体、字号、行高、间距、圆角、阴影；要深色的，深色那套写在 @media (prefers-color-scheme: dark) 里
  index.md            每屏一行，再加组件清单（表头见 design.md）
  mockups/
    components.css    组件的样式，类名就是组件清单里的名字
    index.html        总览页：每屏一张截图、点开是稿子，给人看的
    Home.html         一屏一个文件，默认状态
    Home--empty.html  别的状态各一个：--empty --loading --error --long
  shots/
    Home.png          每个稿子一张截图，文件名和稿子一样；深色的 Home.dark.png
```

稿子是给开发照着做的，不是上线的代码，但要写得让开发能直接搬结构。

## 稿子的写法

- 普通 HTML + CSS，不用框架、不用构建、不写 JS。不同状态写成不同文件，不靠脚本切。
- 每个稿子只引两份样式：`../tokens.css`、`components.css`；页面自己的布局写在 `<style>` 里。颜色、字体、字号、圆角、阴影只用 `var(--…)`，稿子里不出现裸的颜色值；间距用 tokens 里的那几级。
- 一个组件只在 `components.css` 里写一次，各屏用同一个类名。组件清单里没有的，先加进清单再用。
- 尺寸照总纲：手机屏 390×844；桌面网页 1440 宽。网页是流式的：`max-width` 容器、`%` / `rem` / `fr`，手机宽度下菜单收起、表格在框里横向滚，不写死页面宽度。
- 布局用 flex / grid + `gap`，不靠空格和零散的 margin 排兄弟元素。
- 真元素：按钮用 `<button>`，链接用 `<a href>`，输入框配 `<label>`；只有图标的按钮写 `aria-label`。
- 图标：内联的线条 SVG，不用 emoji。图片没有素材就画一个标了字的占位块，好过画个蹩脚的。
- 文案用真的：照总纲和产品写，不用 lorem ipsum、不写「欢迎来到我们的网站」。缺的事实（价格、日期、地址）写成 `[价格]` 这样的占位，不编。不编数字和统计。
- 中文界面：字体栈 `"PingFang SC", "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`；标题要有个性可以用 Noto Serif SC 这类，从 Google Fonts 加载（一个 `<link>`），后面跟系统字体兜底。
- 手机稿不画假的状态栏、假键盘。

## 设计得好

- **先找上下文。** 已有产品就先读它的代码里的样式、组件、品牌素材，照它的视觉语言接着做；从零造一套是最后的办法。改已有的界面，数值照源码抄，不凑整。
- **定一个说得出名字的方向。** 总纲的气质（三个词，「像……不像……」）落成一套小规范，写进 `tokens.css`：
  - 字体一对：标题一款有性格的，正文一款中性好读的。
  - 底色和文字色带一点色调（暖、冷或中性），不用纯白纯黑铺满。
  - 强调色 0–2 个，彼此明度、彩度相近、只换色相（用 oklch 算）。有品牌色就用品牌色。
  - 一个主色压住全局、强调色用得少而准，好过各种颜色平均撒。
- **要有意图，不求花哨。** 极简就做到克制、精确，间距和对齐经得起细看；丰富就把效果做足。每次出稿别都收敛成同一个样子。
- **层级。** 每屏最重要的那件事一眼看到；主操作一屏只有一个，可以在长页面里重复出现，不放三个抢眼的按钮。
- **不要 AI 味：** 大面积渐变、emoji、左边一道彩条的圆角卡片、处处卡片加阴影、一排三张一样大的特性卡、没用的数字和图标、空话文案、Inter 配紫色渐变这种默认搭配。
- **不填充。** 一块显得空，是版式要解决的，不是加内容的理由。觉得该多一屏、多一段，写进报告让总控定，不自己加。
- **看得清、点得到。** 正文对比度至少 4.5:1（24px 以上 3:1），灰色小字和彩色底上的白字最容易不够，压暗。点击区至少 44px。要区分的颜色明度也要不同，不只靠色相。
- 不照抄别家产品有辨识度的设计。

## 每批怎么做

1. **方向。** 第一批先定方向：交法是「直接出」的，自己定一个，理由写进报告；「先挑方向」「每批都看」的，先出两三个真不一样的方向（每个方向只做最核心的一屏，粗一点也行），各写一句好在哪、代价是什么，交给总控等用户挑。
2. **规范。** 写 `tokens.css` 和 `components.css`。后面每批照用，要加先加在这两份里。
3. **稿子。** 照这批的分批任务，一屏一屏写，每屏的状态都写齐。
4. **截图。** 每个稿子一张整页截图，宽度照平台：
   ```bash
   npx playwright screenshot --viewport-size=390,844 --full-page --wait-for-timeout=800 \
     "file://$PWD/design/mockups/Home.html" design/shots/Home.png
   ```
   桌面网页用 `1440,900`；要深色的加 `--color-scheme=dark`，存成 `.dark.png`；总纲说网页手机上也要用的，每屏多截一张 390 宽的 `.m.png`。没装浏览器先 `npx playwright install chromium`（要联网，沙箱里请总控让用户放行）。Playwright 是截图工具，不写进项目依赖。（这条命令照 Playwright 命令行的说明写，还没在真项目里跑过；参数报错就看 `npx playwright screenshot --help`。）
5. **自己先看。** 一张张看截图，对着下面审稿的六条先改一遍。
6. **派人审。** 开一个子 agent 审（最强档，思考强度中；不是你自己），给它下面那段话。它列的问题一次改完，重截，再审一次。**最多两轮**：第二轮还剩的，写进报告让总控定，不在原地来回改。开不了子 agent 的环境，写进报告，由总控验收时派人审。
7. **收尾。** 更新 `index.md`（前五列）、总览页；只提交 `design/` 下自己的文件，推自己的分支；报告照开线时说的写。

给审稿子 agent 的话：

```
你是审稿的，只读，不改文件。看设计线出的这几屏截图，挑出要改的地方，10 分钟内交。
- 截图：design/shots/<这批的几张>
- 总纲：.code-autopilot/design/brief.md（气质、一定要有的、不要出现的、这批每屏的内容和状态）
- 稿子源文件：design/mockups/<这批的几个>.html、design/mockups/components.css、design/tokens.css
逐条看：
1. 第一眼：给没见过的人看，会以为这是什么产品？和总纲的气质对得上吗？像不像套模板、像不像 AI 随手出的？
2. 层级：每屏最重要的那件事是不是一眼看到；主操作是不是只有一个。
3. 「不要出现」和 AI 味：大面积渐变、emoji、左边彩条的卡片、处处卡片加阴影、没用的数字和图标、空话文案。
4. 细节：对齐、间距节奏、字号层级不超过五级、对比度（正文 4.5:1）、点击区 44px、文字有没有截断或溢出。
5. 状态齐不齐：空的、加载中、失败、内容很多。
6. 稿子里有没有写死的颜色、字号（都该是 tokens.css 的变量），同一个组件各屏是不是一个样。
每条写：哪张截图、哪里、问题、建议怎么改。按影响大小排，最多 15 条；看不清的写「拿不准」，不硬说错。
```

## 改稿

总控转来的意见（用户的、对稿时发现的），改对应的稿子，重截图；动了 `tokens.css`、`components.css` 的，用到的屏都重截。同一批改过的屏再走一次第 6 步。旧的截图不留，git 里有。
